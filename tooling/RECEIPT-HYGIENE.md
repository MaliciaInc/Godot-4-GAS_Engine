# Regenerating the release receipt set

`artifacts/gates/GAS_ENGINE_FINAL/` holds the release evidence.

**This procedure has been run.** The set was regenerated at the freeze on
2026-09-03, checked against every point below, and the identity gate now reads
it. `FREEZE.md` in that directory names the commit. What follows is kept
because there will be another release, and because the reasoning is what makes
the steps safe to repeat rather than copy.

## Why this note is not in there

An earlier draft of it was, and it broke its own check twice over.

The check below looks for the pre-rename product name, the pre-rename suite
verdict prefix, and absolute paths. A note documenting those has to mention
them, so a note kept inside the directory matches every search meant to certify
that directory. Worse, one step of the procedure points the identity gate at
that directory — and the gate would then fail on the very file explaining the
cleanup.

So the procedure lives with the tooling that implements it, and it names none of
the strings a checker looks for. Where a shape is needed, it points at the file
that already enumerates it. `GAS_ENGINE_FINAL/` holds evidence; it does not hold
the instructions for producing evidence.

## What was stale in there, and why

Before the freeze, nine of its files carried an absolute path from the machine
that produced them, and the suite receipt carried the verdict prefix from
before the rename. Neither was an accident: the generators emitted them.

That is fixed at the source, in three places, so a regenerated set comes out
clean rather than being cleaned afterwards:

- `tooling/gates/lib/gate_report.py` rendered the resolved project root into the
  `- Project:` row of every gate's Markdown. It renders a fixed placeholder now,
  and `Report` no longer has a root to be handed — an unread field on a
  dataclass every gate fills in is an invitation to print it again.
- `tooling/verify.ps1` wrote the full command line into every `.log`, with the
  repository spelled absolutely twice. It is written relative to the repository
  now; the child process already runs with the repository as its working
  directory, so that is the command that actually ran.
- `verify.ps1` also captured the gate self-tests' own output into
  `gate-self-tests.log`, and two of those tests point a gate at a missing path
  under the user's profile on purpose. The gate is right to name a path it
  cannot read, so the stage runs `unittest --buffer`: a passing test's output is
  held, and only a failing one's is shown. Fixing those two tests would have
  left the next one free to do the same thing.

`tooling/gates/tests/test_gate_report.py` pins the first. The other two have no
unit harness — there is no PowerShell test runner here — so they are checked by
running `verify.ps1` and reading the receipts it produced. That reading is what
found the third; the first two were visible from the source.

## The procedure

1. Regenerate the set at the frozen commit:
   `verify.ps1 -TaskId GAS_ENGINE_FINAL`.
2. **Identity.** In `SKIP_PREFIXES` in `tooling/product_identity.py`, replace
   the single `artifacts/gates/` entry with one entry per *historical* receipt
   directory, each spelled in full: `artifacts/gates/GAS_ENGINE_REBRAND_BASELINE/`,
   and the same shape for `T0/`, `T0-baseline/`, `T1/`, `T2/`, `T7/` and `T11/`.
   `SKIP_PREFIXES` is matched against the repository-relative path, so a bare
   directory name would skip nothing. `GAS_ENGINE_FINAL/` then becomes the only
   receipt set the gate reads. Then run that gate. It owns the forbidden vocabulary, so
   this is the check and no list needs restating here; it covers the old verdict
   prefix too, because the bare product word is one of its tokens and the match
   is case-insensitive.

   Not a blanket deletion of the entry, and this was measured rather than
   assumed: with the whole prefix removed the gate reports 1,541 offending
   lines, and only 13 of them are in `GAS_ENGINE_FINAL/`. The other 1,528 are in
   receipts from phases that ran before the rename, where the old name is a
   truthful record of what the project was called at the time. Rewriting those
   would be falsifying evidence, which is the opposite of what this procedure is
   for. History stays skipped; the release set gets certified.

   Those 13 are all regenerated by step 1, so the gate comes out green — checked
   by making the change, running it, and putting it back. Eight of the 13 were
   invisible until `.log` was added to the gate's `TEXT_SUFFIXES`: half the
   receipt set is log files and the gate was not opening any of them, so the
   check would have certified nine files it never read.
3. **Absolute paths.** No file in the set may hold one. The shapes to look for
   are the ones `tooling/gates/tests/test_gate_report.py` enumerates — read them
   from there rather than retyping them. Note that a colon followed by a slash
   is not one of them on its own: it also matches every `res://` path a receipt
   may legitimately name, so the search has to anchor on a drive letter.
4. **Verdict prefix.** The suite receipt must carry the current one, which is
   the string `test/gut_headless_runner.gd` prints.
5. **Fingerprint.** `python tooling/engine_evidence.py
   artifacts/gates/GAS_ENGINE_FINAL` must report both engine stages current, and
   both receipts must say `RESULT: PASS`.
6. Commit the set, and keep step 2's `SKIP_PREFIXES` change in the same commit.

## Do step 2's change last, not early

While a set is still old, skipping it is correct: scanning it would fail
`verify.ps1` on every run until the regeneration, over files nobody is allowed
to touch yet. Clean the set first, then let the gate hold it — in that order,
and in one commit, so the tree is never in a state where the gate is armed
against evidence that has not been regenerated. That is the order this freeze
followed.

A set produced after all three fixes has been checked this way and is clean:
`artifacts/gates/source-fold-tests/`, 2026-09-03.
